# Approved linked news

`/news` reads `/api/v1/public/news`: at most 100 newest visible items from currently approved sources, with publisher, supplied publication date, bounded supplied excerpt and original external URL. Public projections omit feed URLs, reasons, approvals, jobs and audit records. No news is seeded or generated; the empty state is intentional.

Global administrators use `/admin/news` and the shared `/api/v1/news` domain commands to add an approved feed, suspend/reapprove a source, fetch now, and hide/restore an item. Every approval/visibility change requires a meaningful reason and the latest source/item version. Stale edits return 409 and preserve the prior decision. Feed URLs and publisher labels are fixed after creation: suspend an obsolete source and approve the new feed separately. No editorial article authoring is exposed. The private workspace includes up to 200 newest items and 100 latest fetch attempts.

`npm run worker` runs pg-boss `news-fetch` jobs and an hourly UTC `news-refresh-approved` schedule. Manual fetch requests enqueue transactionally with their staff audit record. Jobs recheck current approval before fetching and again before persistence, retry temporary failures up to three times with backoff, and record each failure/success/skipped attempt. URL uniqueness makes repeated fetches duplicate safe; later fetches cannot unhide a moderated item. Public freshness means no successful fetch in 24 hours, while latest-fetch failure is shown separately. Previously stored items remain available when a current feed fails, unless hidden or its source is suspended.

Feed support is bounded RSS 2.0 and Atom XML (1 MiB response, first 200 entries); entries need a safe HTTPS original URL, meaningful title and valid nonfuture publication date (one-day clock tolerance). Missing summaries remain absent. Only supplied description/summary fields are used; full content fields are ignored and excerpts are limited to 280 plain-text characters. HTML never executes. Canonical URLs omit fragments and common tracking parameters and supply identity across all sources.

Production fetch destinations require HTTPS without embedded credentials or custom ports, publicly routable resolved addresses and a pinned connection address; redirects, internal/special-use destinations, XML DTD/entity declarations, oversized bodies and requests over 10 seconds are rejected. The hourly worker must remain running for automatic refreshes.

For deterministic local acceptance only, an ignored `NEWS_FIXTURE_ORIGIN=http://127.0.0.1:<port>` permits that exact origin when `BETTER_AUTH_URL` also uses `127.0.0.1`. It does not permit arbitrary localhost ports or any other private destination. This operator configuration is not set by HTTP or database values. Controlled browser fixtures and screenshots are labelled as fixtures; actual publisher smoke checks are documented separately in `docs/verification/WCP-044.md`. Hosting remains user pending.
