# Ticket implementer contract

The coordinator supplies one published ticket ID, worktree, branch, database and port. Use a fresh context and modify only that worktree. Do not spawn further agents; the coordinator owns the concurrency bound. Read `AGENTS.md`, `docs/agents/execution.md`, `docs/agents/issue-tracker.md`, the assigned issue under `.scratch/world-curling-platform/issues/`, the authoritative `spec.md`, relevant ADRs/CONTEXT and frontend specification. Never use archived drafts as execution sources. Consult `docs/agents/research-index.md` when relevant.

## Work

1. Confirm `git symbolic-ref --short HEAD` is the assigned branch and merge the current local `integration/world-curling-platform` before starting. Do not reset away user work. The coordinator starts a ticket only when its direct blockers are reviewed/integrated/completed.
2. Apply the upstream TDD skill (pointer in `execution.md`) directly; this runtime has no Skill invocation tool. Its approved seams are already agreed in the parent spec: domain public interfaces, real PostgreSQL/HTTP and browser workflows. Use one failing behavior test then minimal implementation, repeated in vertical slices. Explicit independent expected values; no persistence mocks or arbitrary coverage threshold.
3. Implement only the assigned end-to-end slice. Browser and partner adapters share authorized domain commands. Preserve transaction/audit, version/idempotency, privacy and immutable-history safeguards. Do not solve the deferred exceptional recovery engines or add excluded features.
4. Use the assigned isolated database/PORT. Never run mutating tests against another active ticket's database or the crawler. Read source crawler snapshots only as documented. Add migrations with unique descriptive filenames and a sequence prefix after their accepted schema dependencies, not the ticket number; never edit accepted/applied migration contents. Merge sibling migrations carefully. When adding migrations, verify the complete checked-in sequence and seed on a new owned database as well as the incremental path.
   Browser/API fixture files must own their PostgreSQL pool lifetime. Closing an imported shared application pool can break a later file in the combined suite. Keep all inherited suites in standard commands and respect real authentication throttle headers with bounded fixture-helper waits.
   When combining edition, entry and division writes, acquire the edition lock before lower row locks. Entry amendments and division finalization use compatible edition SHARE locks, so their shared lower order is existing entries before division locks; recheck associations after locking. An edition-exclusive scheduler/graph writer must not acquire lower locks before its edition lock. Preserve real lock-barrier regressions when integrating these modules rather than relying on inspection alone.
5. All visible controls must work with persistent data. Verify mobile/tablet/desktop, keyboard focus, honest loading/empty/error/stale states and browser console/network behavior. Inspect actual screenshots. Read installed Next.js guides required by AGENTS.md before writing framework code.
6. Commit self-consistent checkpoints clearly labelled when verification is incomplete; tell the coordinator their SHA for pushing. Do not commit `.env`, runtime data, provider credentials, node_modules or private review assets. The user authorized ongoing pushes to the configured remote.
7. Record actual commands/results/failures/fixes and coverage gaps in `docs/verification/WCP-NNN.md`, with durable screenshot paths. Run applicable inherited suites plus substantive new tests, real PostgreSQL/API checks, typecheck/build and browser acceptance. No test/build pass substitutes for another required layer. Retain complete browser reports before a later focused run overwrites the default report; distinguish each run's scope and source revision. Keep provider checks honest; a missing credential may block that check while unaffected local work proceeds.
8. Before reporting done, merge the latest integration tip into the ticket branch, resolve conflicts and rerun affected checks. Commit final work and report SHA, verification pointer, actual checks and limitations. Leave tracker status/closure to the coordinator/merger.

The integration branch can contain a provisional merger checkpoint or an explicitly rejected ticket while independent checks/corrections continue. A merge title or branch tip is not ticket acceptance. The coordinator's acceptance notification and published tracker state identify completed boundaries; preserve known open findings. Keep source frozen during a running suite. Merge only between runs, retain any interrupted/invalidated report, and never claim a passing subset covers a known missing regression.

Browser selectors should target the application region and the intended current-state element. Next also renders an empty route-announcer alert, and immutable history can repeat revision text. Global alert or unqualified revision-text locators have caused retained fixture failures; scope them without suppressing errors or weakening the expected state. Wait for held route handlers to finish before removing them.

## Environment

Git/npm/Node entry scripts can fail in the Windows sandbox while resolving `C:/Users/brthi`. Reviewed `exec_command` calls with `sandbox_permissions: require_escalated` have worked. Git is 2.20 in that environment (`symbolic-ref --short HEAD`, not `branch --show-current`). Avoid destructive cross-shell operations. Use native PowerShell literal paths and verify workspace containment before recursive deletion/moving.

Check actual Node/npm versions and executable paths at every new session. The system Node was 20.15.0 after the 2026-11-09 resume, although the earlier accepted builds used 20.19.0 and the project requires at least 20.19.0. Use the verified project-local `.runtime/toolchains/node-v20.19.0-win-x64/node.exe` (Node 20.19.0, bundled npm 10.8.2), prepend its absolute directory only to the command's process `$env:Path`, and invoke the exact executable. Invoke npm through that distribution's `node_modules/npm/bin/npm-cli.js`; leave global PATH unchanged. Check actual web/worker/test child executable paths and the engine manifest's `node` field, not only the source fingerprint. Official archive SHA256: `be72284c7bc62de07d5a9fd0ae196879842c085f11f7f2b60bf8864c0c9d6a4f`, verified against `https://nodejs.org/dist/v20.19.0/SHASUMS256.txt`; private records are `.runtime/toolchains/node-v20.19.0-verification.json` and `.runtime/resume-20261109/coordinator-startup.txt`. Retain wrong-toolchain runs as such and rerun required acceptance scopes with the supported runtime.

The primary integration checkout intentionally has no `.env`. For a merger's integration build, use process-scoped `DOTENV_CONFIG_PATH` pointing to the owned candidate configuration, or explicitly supply an owned review database and required local runtime values. Do not copy credentials into the primary checkout or weaken configuration guards to make an unconfigured build pass.

PostgreSQL 13 binaries are installed under `C:/Program Files/PostgreSQL/13/bin`. WCP-001 established an isolated local instance on loopback port 55431, with data under the project's ignored `.runtime/wcp001`. Inspect its setup record before using it; create a separate database per ticket. Docker's daemon was unavailable at preflight. Do not alter the existing unrelated Windows PostgreSQL service/databases. Hosted credentials/domain inputs are separate from local acceptance.

When inherited acceptance includes news, configure one unique loopback `NEWS_FIXTURE_ORIGIN` for that worktree in both its running app and test environment. Run API/browser fixture suites sequentially within the worktree; independent worktrees must not share a fixture listener port. The fixture exception is optional local operator configuration, never a production default. Keep inherited media storage outside the disposable worktree as required by its storage adapter.

The coordinator reviews/merges and pushes completed work, closes only verified tickets and continues the unblocked graph with at most three implementers. Report genuine blockers without inventing successful checks.

Re-probe app and long-lived worker after a leaf-agent handoff. Plain exec session IDs were observed to disappear when an implementer ended; historical successful checks do not establish continued service liveness. Restart only the owned runtime from its exact source/config if needed; Windows detached Start-Process calls require -WindowStyle Hidden. worker:probe starts/stops its own probe consumer and does not leave an event-assessment worker running. Keep API/browser fixtures sequential, check for remnants of an interrupted owned fault-injection fixture, and preserve the actual setup-failure report before a clean rerun.
