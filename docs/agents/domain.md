# Domain documentation

The project uses one domain glossary at root `CONTEXT.md`, architectural decisions under `docs/adr/`, and supporting design/evidence under `docs/planning/`. Preserve this established layout; do not create a second competing glossary to match a newer upstream naming convention.

Use the user's final answers and accepted ADR refinements when an older proposal or earlier interview recommendation differs. The original v0.3 schema is historical input; v0.4 reconciles the interview. Recorded technical defaults remain distinguishable from product requirements and unresolved official-rule interpretations.
