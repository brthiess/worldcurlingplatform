## Delivered behavior

Organizing organizations and disciplines are selected and displayed by name; lookup metadata is also server-scoped. Named exception identifiers can be copied from application details.

World Curling administrators grant an authority name and named reviewer with explicit country, organizing-organization, discipline, category, included-application and excluded-application lists. Empty dimension lists allow all values in that dimension. Country/organization/category and every proposed division must match. Named inclusions bypass dimension checks; exclusions always win. Exactly one matching grant routes a new application to its reviewer; zero or overlapping matches route to the organization's named World Curling administrator. Existing applications retain their recorded responsibility until an explicit reassignment.

Each application stores one authority and reviewer, not independent competing approvals. Only its current responsible reviewer with a live matching grant can make an ordinary admission decision. World Curling can explicitly reassign responsibility to a matching active delegation or an active World Curling administrator, with a reason. A reasoned World Curling override can replace a submitted or decided admission; drafts still require submission. Each change increments the application version and commits immutable attributed history with the responsibility snapshot. Registration and division ranking eligibility remain independent.

Delegations confer no onward delegation, organizer editing or scoring authority. Organizers assign/revoke scorekeeper access only for games in their own event, nominating a registered account by exact email. They cannot grant organizer/reviewer/global roles. Scoped assignment and revocation history retains the recipient/event/game and reason. Actual scoring commands recheck current grants under PostgreSQL locks before source, receipt and version handling; revocation denies even a previously accepted request's replay. No ranking-publication authority is created.

The authority/staff page exposes only server-authorized grants, events, games and history; application queues, details and commands share current responsibility checks. The application screen shows responsibility, inactive/revoked scope, history, explicit WC controls, and read-only edition fields for delegated reviewers. Unassigned users receive empty/denied screens. All controls call persistent guarded commands.
