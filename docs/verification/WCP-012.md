# WCP-012 verification

Implemented locally on 2026-11-08 in `ticket/WCP-012`, worktree `.worktrees/WCP-012`. The coordinator owns review, integration and tracker closure. Published issue: `.scratch/world-curling-platform/issues/12-create-accounts-approve-player-claims-and-edit-profiles.md`.

## Delivered behavior

Visitors register at `/account`, verify the real generated email link, and sign in without any player/team/organizer/scoring/grant authority. Password recovery sends a real private local link, resets the credential once, and revokes database sessions. The existing `/admin` demo-persona sign-in remains available; ordinary account sign-in and profile management are linked from it.

Independent player records have no required account. The repeatable seed adds two explicitly fictional public players with blank biography and unknown handedness; it preserves later claims and edits. `/players` and `/players/[id]` read public APIs selecting only id, name, origin, biography and handedness. They disclose no accounts, contact fields, claim evidence, decisions, links, sessions or tokens.

`/account/profile` supplies a private request/status/history form, global World Curling administrator approval/rejection with a reason, and approved-owner biography/handedness forms. Server commands validate exact input fields and enforce the current session, origin, real global administrator grant, exact approved owner, 500-character plain text, left/right/unknown handedness and current profile version. Administrators and organizers cannot edit someone else's controlled profile just because of their role. Claim ownership adds no unrelated role grants.

Unique constraints allow only one approved account per player and one player per account. Claim requests are duplicate-safe by request ID and preserve their original payload. Competing approvals serialize and return a conflict rather than creating multiple links or partially reviewing a claim. Link/review/audit and profile/version/history/audit changes commit in the same PostgreSQL transaction. Final claim decisions and profile-history rows are protected against later update/deletion by database triggers. Photo work is reserved for WCP-013.
