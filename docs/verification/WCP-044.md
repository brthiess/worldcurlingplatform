## Delivered boundary

Fans open `/news` for concise linked cards: safe headline, configured approved publisher, supplied publication date, supplied excerpt when present, original publisher link, source freshness and recoverable fetch errors. No news is seeded, generated or authored. The worker ignores full article/content fields and stores at most 280 plain-text excerpt characters. Public reads explicitly select public fields and require both an approved source and a visible item.

Global administrators use `/admin/news` to approve a source with a reason, suspend/reapprove it, enqueue a real fetch, and hide/restore items with a reason. Organizer/reviewer/ungranted accounts cannot manage this platform-wide resource. Source/item versions prevent stale overwrites. Source approval/visibility decisions have transactional immutable audit records. URL uniqueness deduplicates across sources and retries; future fetches cannot undo a hide decision. Feed publisher/URL are fixed after source creation; suspend an obsolete source and approve the replacement separately.

A real PostgreSQL-backed pg-boss `news-fetch` handler rechecks approvals, stores each fetch outcome, retries temporary failures with backoff (up to three retries) and retains prior valid items during feed failure. Hourly UTC `news-refresh-approved` schedules approved sources while the worker is running. Public freshness is stale after 24 hours without success; latest failure is separately projected without private failure details.

HTTPS URL validation excludes credentials/custom ports and private/special-use literal addresses. Fetches resolve all addresses, reject nonpublic destinations, pin the connection to a validated address, and reject redirects. Responses are bounded to 1 MiB and 10 seconds of network request time. RSS/Atom parsers reject DTD/entity declarations and invalid XML; invalid/missing/implausible dates and unsafe item URLs never become public. No full-article request is performed. Staff request bodies are bounded to 4 KiB while streaming. The exact loopback fixture exception is operator configured, restricted to a loopback app and a single loopback HTTP origin, and is absent unless explicitly configured.

Operational details: `docs/news.md`. Hosting/domain remain explicitly user pending; no paid provisioning, Render action or hosted claim occurred.

## Red/green and corrected findings

- RSS normalization first failed with a missing module, then passed independently specified publisher/title/date/excerpt/URL values and canonical duplicate removal. Atom coverage proves summary-only projection, ignoring full content, unsafe URLs, missing/future dates, DTDs and malformed XML.
- Reserved-address/impossible-calendar test failed because a documentation address was considered public; corrected IPv4/IPv6 special-use checks and calendar rollover validation. The test now rejects literal private, mapped loopback, documentation and reserved destinations.
- Real PostgreSQL source workflow initially failed with a missing service. It now proves unapproved fetch skip, approval, repeated fetch producing one item, public hide filtering, suspension filtering and persisted 503 failure while retaining the previous successful fetch.
- HTTP boundary first returned 404 where 401 was expected; routes now prove anonymous 401, nonglobal roles 403, cross-origin 403, private feed destination 400, unapproved fetch 409, stale source version 409, approval persistence and private-field exclusion from public JSON.
- The real pg-boss fixture first timed out with no item because no news handler existed. After wiring, a controlled 503 is persisted and retried to a successful job with exactly one item despite a duplicate entry. An abandoned job from that failing run consumed a fixture's first response during an early rerun; fixture servers now isolate exact per-test paths so other queued jobs cannot consume their response sequence.
- A source reason made only of script markup initially returned 200 and stored an empty plain-text reason. The new failing HTTP check drove validation after safe-text projection; final behavior rejects it with 400.
- Real source audit failure injection proves approval/source creation rolls back atomically. Retrying after restoring the audit succeeds; direct audit rewriting is refused by PostgreSQL. Two different source updates at one version permit one commit and reject the other.
- The initial public browser test failed on the missing page, then the administrator add/suspend workflow passed. Expanded browser acceptance caught a raw `Failed to fetch` message and an overly broad Playwright alert locator including Next's route announcer; the UI now gives a useful recovery message and the test scopes its alert to main content.
- An early typecheck during active Next dev output encountered a partially regenerated `.next/dev/types/validator.ts`. Stopping dev and running production build/typecheck passed; no generated-code workaround was committed.
- Initial parser install 5.5.8 had one moderate builder advisory; upgraded to fixed 5.12.0 and repeated normalization tests/audit successfully.
- An attempted parallel focused browser/API run shared fixture port 3244 and correctly failed with `EADDRINUSE`. Required final fixture suites run sequentially; fixture pools and servers have owned lifetimes.

## Actual external publisher smoke, distinct from fixtures

The first approved `https://worldcurling.org/feed/` smoke honestly recorded a failed fetch and zero items. A diagnostic revealed an implementation bug: Node 20's connection lookup requested `options.all`, while the pinned DNS callback returned a single-address shape. Controlled fixtures use an IP literal and had not exercised this branch. Corrected the callback to return the required address array without weakening address validation/pinning.

Repeated the same real approved publisher fetch: 71,704 XML characters received, 10 actual items persisted, `lastSuccessAt=2026-11-08T17:52:39.013Z`, `lastError=null`. These are actual publisher items; none were invented. No full article body was fetched or stored. The public card's real external link was also opened through Chromium from `/news`: `https://worldcurling.org/2026/11/wwcc2028-host-announcement/` opened at that exact original URL with a nonempty page title. These network-dependent smoke results are separate from repeatable deterministic fixture tests.

## Limits

Feed support is RSS 2.0/Atom XML, not JSON Feed or RDF; redirects must be reviewed as a new direct feed URL. Public reads are limited to 100 latest items; moderation shows 200 latest items and 100 latest attempts. Excerpts are bounded supplied summaries rather than authored news. No article editor, full-article republication or paid/hosted integration is supplied. Automatic refresh requires the worker process. Provider availability is outside the deterministic fixture tests.

Coverage does not claim exhaustive DNS rebinding/IPv6 routing, parser-library internals, arbitrary malformed-feed fuzzing, TLS failures, all queue shutdown/expiry races, or passage of an actual hour for the cron schedule. Destination predicates, real connection callback, status failures/retries, canonical deduplication, audited decisions, public privacy and browser controls have the separate checks above.
