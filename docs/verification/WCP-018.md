## Behavior and evidence boundary

Separate event schedule versions, current-authority checks, atomic audit/snapshots and immutable command receipts protect create/revise-session and assign-existing-game commands. Same-request retry replays its exact receipt; altered retry, stale version and unrelated scope fail. Commands serialize on the edition, lock its games against scoring and hold referenced entries while reading lineup versions. A guarded upsert prevents a concurrent identifier collision from moving another division's session. Scheduling writes only session number/time/duration and game draw/sheet, preserving score versions/source, participants, lineups/results and downstream evidence.

Organizer conflicts compare all divisions within the edition's venue, using half-open planned intervals; normalize sheet labels and include known entries and all non-coach declared/defaulted lineup members (including rotating five). Missing/incomplete/provisional coverage is explicit. Player overlap is declared scheduling evidence, never delivered-stone participation. No optimization or format generation.

Public and organizer draw states derive actual games: all confirmed → completed; any live/confirmed with unfinished games → live; empty/all scheduled → scheduled. Time passing does not create play; actual live evidence takes precedence even if its planned timestamp is future. Selection uses latest active planned start, otherwise latest completed, otherwise earliest scheduled; next remains earliest scheduled even if overdue. The test-only shared scoring fixture moved from future2040 to older2000 so its real activity does not become the fixture homepage's latest draw; production selection is not filtered to conceal activity.
