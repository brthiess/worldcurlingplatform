## Delivered behavior

The linked player selects a PNG/JPEG/WebP, previews it locally, sees byte-upload progress followed by server processing, and submits privately. One pending request per player prevents replacement during review; identical request/content retries return the original asset. History shows pending/approved/rejected status and reviewer/time/reason. The current public image stays visible throughout a pending or rejected replacement.

Global administrators see the current public image alongside the exact processed submission, its dimensions and fingerprint. Both images must load before a decision; an unavailable comparison disables review and offers refresh. Reviews include the expected digest and current before-image reference. PostgreSQL locks serialize competing upload/review operations. Decision, public-image reference and audit commit atomically; final history and asset metadata cannot be changed/deleted. Replays must match actor/reason/content. Public APIs expose only the current approved processed asset; private previews require the submitting owner or current global administrator.

Sharp validates MIME against actual decoder format, fully decodes input, rejects corrupt/truncated/tiny/excessive-pixel/animated images, rotates, strips metadata and re-encodes PNG at up to 1200px. Limits: 5 MiB input, 64px minimum each dimension, 16 megapixels, one frame. Originals are discarded. Exclusive file creation and synced bytes precede submission metadata; SHA256 is checked on every preview, public read and review. Replacement bytes on disk fail closed rather than publish different content.
