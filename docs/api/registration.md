# Division registration

`/admin/registration` is the actor-scoped organizer/representative interface. Create an event entry through `/admin/entries`, then request its admission separately. An entry lineup does not reserve capacity.

- `GET /api/v1/registration`: current actor, scoped divisions/terms, remaining places, scoped entries with independent admission versions and effective expiry, and the actor's immutable command receipts.
- Same-origin `POST /api/v1/registration`: `{action,requestId,divisionId,version,...}`. The optional `X-WCP-Actor` must match the actual session. UI commands always bind this header and retain their exact serialized bytes in actor-bound tab storage until acknowledged/refreshed or reconciled.
- `open`: organizer/global administrator; version `0`, complete `terms` (`mode`, `capacity`, `requirements`, `feeMinor`, `currency`, `paymentTerms`, `paymentWindowMinutes`, `format`, `formatNotes`). Requires an approved, published edition and no existing game in this division. Terms are immutable after opening. Format notes document the selected family's configuration; generated competition graphs remain a separate command.
- `request`: organizer or current exact team-season representative with `submit`; `entryId` and current **admission** version. Open mode admits a zero-fee entry or creates an unpaid hold; reviewed mode records pending review without consuming capacity; invitation-only mode requires an explicit invitation. A full open field records a waitlisted state without a reserved place.
- `accept`: organizer/global administrator, `entryId` and admission version; reviewed acceptance admits zero-fee entries or establishes the payment deadline. Capacity exhaustion is a conflict. Invitation-only acceptance also requires an invitation.
- `invite`: organizer/global administrator, pending entry in invitation-only mode; no reserved capacity until a subsequent place request.
- `expire`: organizer/global administrator, division terms version; materializes expired holds and returns their entry IDs. Reads and capacity counts already treat a deadline at or before the database clock as expired, so release does not depend on a worker tick.

All capacity/expiry writes acquire the edition exclusively before lower row locks, recheck the division association and current actor authority before receipt replay, and capture `clock_timestamp()` after waits. This deliberately serializes capacity decisions within an edition while preserving accepted entry/finalizer SHARE lock ordering. No command can revive expired holds or promote the waitlist automatically. The immutable command/audit commits with the state change; a retry returns its original receipt and never extends a deadline. Always read current state after replay; an original held receipt may now describe an expired reservation.

`event_entry.entry_admission` retains submission origin. `admission_state`, `admission_version` and `reservation_deadline` describe capacity/admission independently of lineup versions, payment accounting and ranking assessment. `canEnterDraw` is the registration domain contract: configured divisions permit accepted entries only; unconfigured legacy organizer-recorded fixtures retain their prior sporting behavior. WCP-019 owns its draw field adapter and must consume this contract after the two accepted slices meet. Do not rewrite played participants.

No checkout, charge settlement, provider event, withdrawal or waitlist recovery command is introduced here. Fee-bearing entries remain unpaid holds. WCP-010 owns charges/fee exceptions, WCP-011 ordinary withdrawal/replacement, and WCP-028 verified provider settlement. Late payment after release must be flagged for staff attention rather than reclaiming a place; the domain payment disposition explicitly classifies expired/nonheld reservations this way. No paid or ranking-eligible status is inferred from admission or a redirect.
