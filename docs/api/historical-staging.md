# Historical import staging

World Curling administrators use `/admin/imports` and `/api/v1/imports`. Every read and command checks the current session/grant; the worker checks the queued actor's current grant again while holding its transaction. Staging creates private evidence only. It writes no canonical events, players, teams, games, results or ranking publications, and grants no human certification.

An operator creates a private NDJSON file using `python scripts/export-crawler-representative.py --snapshot <frozen-versions.sqlite> --registry <paired-registry.json> --manifest <backup-manifest.json> --hammer-proof <retained-proof.json> --hammer-html <retained-game.html> --output <new-private-export.ndjson>`. The bounded adapter verifies the documented frozen file hashes, uses SQLite URI `mode=ro&immutable=1` plus `query_only`, pins revision 690 consistently, and preserves its schema/revision metadata. It imports no crawler modules and opens no mutable crawler database. Inputs and output must be separate; output uses exclusive creation. Export proof reports before/after hashes. Keep source exports, HTML and reports private and ignored.

Set the server/worker-only `CRAWLER_IMPORT_EXPORT` to that file. A browser cannot submit a path, URL or arbitrary upload. GET without parameters returns the configured file digest and recent jobs. POST `{action:"stage",id,sourceDigest}` queues one job bound to that exact digest. Repeating the same identifier/actor/content returns the original job; a conflicting command is rejected. POST `{action:"retry",id,sourceDigest,requestId}` deliberately retries a failed job. Retrying the exact request identifier cannot create another attempt, including after a second failure. Revoked actors cannot retry. Browser commands retain actor-bound original bytes across uncertain acknowledgements/reloads.

Every supplied request identifier must be a string of 1–80 ASCII letters, digits or hyphens. Stage defaults its request identifier to the job identifier; an optional explicit valid identifier is supported and must be repeated with the same complete command. Retry requires an explicit identifier. A different/unrecorded request cannot reuse an existing stage job identifier as a success acknowledgement.

`GET ?job=<id>` returns job progress, frozen manifest, game previews, issues, record digests and audit history. `GET ?job=<id>&record=<fully-scoped-key>` returns one retained source record and its original line/digest/ordinal. These are administrator-only endpoints. The UI shows up to 100 games and 1,000 issues/record digests; batch counts describe the full frozen batch. Recent history is limited to 100 jobs. Input is bounded to 256 MiB, 100,000 records and 2 MiB per line.

Authorized job detail also identifies the current reader and immutable command receipts. Read-only recovery requires that current account, original job/actor/request/source association, exact imports endpoint and SHA-256 of the complete parsed command using the server's `canonicalEntryCommand` contract. Changed action/path/body or another account leaves the journal retained and editing locked. Canonical-equivalent original content can reconcile using reads alone, with no POST to any endpoint. Exact committed POST receipt replay also avoids the worker's mutable job-row lock; genuinely new commands retain the transaction, current-authority, locking, queue and audit safeguards.

The PostgreSQL job/audit/pg-boss enqueue commit together. The worker streams records, translates game previews and freezes all source lines, order, per-line hashes, source metadata, evidence, raw hammer body and reported interpretation in one transaction. A failed parse, changed byte digest, missing relationship or audit failure leaves no partial review batch. Frozen evidence rejects updates/deletes and later appends. Reconstructing ordered source lines plus newlines reproduces the exact file SHA-256.

Source evidence records are counted separately from unique games; neither count claims total historical coverage. Partial lineups, source `X` cells, null scores, unreported timezone/draw relationships, unresolved player/core identity and missing historical parser versions remain visible. The Baden 2025 final's reported first-end hammer preserves a specific retained marker and same-game publisher corroboration, separately from the original crawler's unknown game-parser version. It establishes no universal marker convention or human certification. The Korean example remains unknown. A platform translator version is distinct from source parser/export provenance.

This representative adapter selects four games and their context, plus two colliding entry leaf keys retained under different parents. Broader loading, curated mappings, exact-content approval and canonical idempotent reruns belong to WCP-015; historical ranking browsing belongs to WCP-016.

Browser acceptance starts with a newly migrated/seeded owned database before any staging jobs. The genuine empty-history check runs by default, followed by actual staging workflows. To repeat the complete file, use another owned database and matching app/worker configuration; do not delete retained batches or reset earlier evidence. Run API/browser fixtures sequentially and keep the source export fixed throughout each run.
