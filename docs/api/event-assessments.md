# Four-player event assessments

`/admin/event-assessments` and `/api/v1/event-assessments` are private to a current global World Curling administrator. An organizer, representative, profile owner or scorekeeper cannot read the global source, roster, rank or calculation evidence. Writes require the configured Origin and honor the actor-bound exact-command recovery journal.

`GET` lists divisions and rule editions. `GET ?division=<id>&rules=<record-id>[&assessment=<id>]` returns a reviewed source digest, latest frozen sporting finalization, scoped official roster evidence, assessment history, selected immutable input/result bytes and durable job state. The selected assessment must belong to this division. Responses are never cached.

`POST {action:'calculate',divisionId,version,sourceDigest,requestId,evidence}` records a direct assessment revision and a pg-boss delivery atomically with audit/receipt. `version` is the latest assessment version (zero initially), while `sourceDigest` is from this exact current review. Unknown required evidence results in a durable **blocked** job with no SFM/awards. Missing sporting finalization cannot queue. Stale source/history returns409. No manually supplied total is consumed.

The typed evidence shape is `AssessmentEvidence` in `src/domain/event-assessment-input.ts`. The UI offers category, ranking date/cutoff, rationale and entry eligibility/ranks, plus complete sourced-evidence import/inspection for detailed provenance and participation segments. Sources retain HTTPS URL, inspected edition, actual retrieval timestamp and SHA-256. Historical field ranks/points, edition status, event registration/compliance/results evidence, qualification/playoff game classification, official roster review and actual throughout-play participation are separate facts. A source URL does not authenticate a fictional fixture or convert staff assertions into official rule endorsements.

Each entry has a sourced eligibility decision and rationale. Eligible entries additionally need `rosterReview:{recordId,version,sourceId,note}` and `games:[{gameId,segments:[[playerId,...],...]}]`. The roster review explicitly approves only event-relevant official regulars/identities, the exact current platform roster reference, source, rules and effective interval. It neither reviews nor consumes starting-entitlement amounts, point allocations or continuity. A draft WCP-032 starting record stays draft. Missing unused carryover does not block an event award. Missing/stale/unsourced official regulars or unresolved relevant identities block it. Defaulted/declared game lineups alone cannot prove actual participation; sourced segments must cover throughout play and agree with the frozen identified game lineup. Four regulars require at least three on ice; five regulars allow no outsiders. Staff review cannot waive these required checks. Exemption/penalty and forfeit branches remain unresolved rather than receiving invented points.

All frozen games must be classified exactly once as qualification or playoff. Wins and qualification records derive from immutable sporting results. Where a losing-record qualifier's reduction depends on the first playoff game, evidence supplies `firstPlayoffGameId`; it must belong to that entry and stage. A single playoff game or all-playoff-wins needs no invented scheduled clock. Sporting placements remain authoritative; there is no automatic sporting qualification tiebreak or format engine here.

The manifest includes canonical UTF-8 contents and SHA-256, exact finalization version/bytes/digest, reviewed rule revision/data/sources, explicit application policy, pre-event snapshot/cutoff/field, event source evidence, scoped official roster revisions/current status, derived calculation field, actor/request/audit and engine. Worker deliveries use only this frozen manifest. Result bytes/digest and their exact input-digest association are immutable. Later roster, source or score changes cannot rewrite a prior award. Corrections queue a direct new revision; no transitive reassessment engine is supplied.

`POST {action:'retry',divisionId,assessmentId,version,requestId}` requeues a failed delivery with its original immutable manifest. Blocked evidence needs a new assessment revision. Current staff authority and division association are checked before every receipt replay. Exact actor/request duplicates return the original association; conflicting reuse returns409. pg-boss automatic retries and a duplicate delivery cannot create a second result/audit. Application state records queued/completed/blocked or failed delivery, attempts and error; queue insertion shares the assessment transaction through pg-boss's transaction adapter.

## Recorded application policy

Engine `wcp.four-event.2026-27.v1` pins policy `wcp.four-event-policy.2026-27.v1`. Official source tables establish the ordinary strength/factors/awards. They do not fully specify stage order, midpoint convention, exact cutoff instant or threshold timing. The separately recorded **application interpretation** uses exact rational arithmetic; contributions → scale → teams factor → tour floor → category cap/importance → single-knockout reduction → final nearest tenth (positive midpoint half-up); final SFM determines tour series. Award values stay exact rationals and have separate decimal display. This does not alter WCP-032's earlier unresolved interpretation records or claim an official clarification. The preceding Tuesday is strict in the venue timezone, including the prior week for Tuesday starts; the exact historical ranking snapshot instant must be sourced on that date. Competing excluded entries stay in N while contributing/earning zero, under the recorded application policy. Special categories bypass the tour historical floor. Worlds use fixed strength and do not require unused ranks.

Rank200's overlapping official bands, sub-eight award entitlement, forfeits, eligibility exemptions and season penalty arithmetic remain blocked. An explicit sourced event exclusion is preserved with zero award and does not calculate an unstated season deduction. No world list, publication, carryover/continuity calculation or automatic downstream cascade is implemented.
