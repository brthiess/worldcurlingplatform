# Entry charges and external receipts (WCP-010)

`/admin/entry-charges` is the private financial workspace. `GET /api/v1/entry-charges` returns current actor/scoped divisions, append-only fee versions, entry charges, exact integer balance components, credit history, effective admission and current-scope command receipts. Current global administrators and edition organizers can read/manage that edition. A current exact canonical team-season representative with the `payment` action can read that entry's ledger only. Submit/amend/withdraw actions and player-profile links confer no financial right. Representative payment grants do not permit staff attestations, waivers or fee edits.

Same-origin `POST /api/v1/entry-charges` requires `{action,requestId,divisionId,version,reason,...}` and binds optional `X-WCP-Actor` to the real session. Browser commands retain the original serialized body/request ID in actor-bound tab storage through uncertain outcomes and reloads.

- `freeze`: staff only; `entryId`, charge version0, `expectedFeeVersion`. Freeze the normal fee for an entry before admission if desired. Manual/invited origin never implies a waiver or receipt. Otherwise first admission request/invitation freezes the charge transactionally.
- `discount`: staff only; `entryId`, current financial version, positive integer `amountMinor`, frozen `currency`, reason. Partial reductions are allowed up to the remaining due.
- `waiver`: same, with the exact full remaining due; a partial exception uses `discount`.
- `external_receipt`: same, plus a nonempty `externalReference`. This is staff attestation of funds actually received elsewhere, **not** a provider transaction or online-payment success. Exact references are unique within a division to prevent accidental duplicate counting. No conversion or overcredit is allowed.
- `revise_fee`: staff only; current fee `version`, new `terms:{feeMinor,currency,paymentTerms}` and reason. Appends a fee-specific version for future charges. The division currency stays fixed; capacity, requirements, format and reservation window remain as opened. Existing charge amounts, currency, terms and credit history never change.

Financial versions begin at1 for a frozen charge and increment once per appended credit. Fee versions independently begin at1 for supported original opening terms. The supported ISO currency set is deliberately bounded to CAD/USD/EUR/GBP/CHF (two decimal places), JPY (zero) and KWD (three); maximum amount is100,000,000 minor units. UI inputs/display use explicit currency amounts; API storage remains exact integers. No implicit foreign exchange or mixed-currency ledger is supported.

When creating a **new** charge, `expectedFeeVersion` must match the current reviewed fee version, checked after authorized exact receipt lookup. A fee edited since display causes409 and requires refresh/review; it never silently charges a new amount. Existing frozen charges and exact receipts remain valid after fee revisions. Narrow compatibility permits omitted quotes only for matching original immutable version1 terms; after any fee edit a new charge requires an explicit current quote. Admission request/accept/invite commands use the same guard. Registration workspace exposes `feeVersion` and current new-charge pricing; entry charges retain their own original `feeVersion`.

The first admission request, review acceptance or invitation freezes the entry's fee. An explicit staff freeze can do so earlier. A future fee revision affects only entries without a charge. Migration backfill prices previous admissions only from supported retained **original** opened terms; unknown/unsupported legacy terms remain unpriced, never zero/paid. Historical admissions without a provable original fee cannot be repriced from a later fee version.

Every mutation, reason/history and audit/receipt commits in one PostgreSQL transaction. Edition UPDATE precedes lower entry/division locks; time is `clock_timestamp()` after waits. Current scope/context is checked before exact receipt replay, while quote/freshness/collision checks follow replay. Concurrent adjustments cannot overcredit or duplicate an external reference. Exact retries are read-only and never repeat a credit or admission transition.

Clearing a live held balance accepts that existing place under the capacity lock, retaining current known-team collision protection. At/after effective expiry, or without a live hold, clearing the balance does not reserve/revive a place: admission remains separate and the workspace requires staff attention. Waitlists do not promote automatically. Roster, ranking, withdrawal and refund decisions remain independent. There is no checkout, provider-event processor, refund engine or automatic exceptional settlement in this slice; WCP-028/029 own later online collection/refunds.
