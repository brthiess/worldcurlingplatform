# Four-player overall draft review

`/admin/overall-rankings` and `/api/v1/overall-rankings` require current global World Curling administrator authority. Writes require the configured Origin and support actor-bound retained-command recovery. Organizer, representative and profile authority confer no access.

`GET` lists source editions. `GET ?discipline=men_four|women_four&date=YYYY-MM-DD&rules=<id>` returns the entire2026-27 registration universe, every approved completed-season division in that discipline/date interval, current full starting readiness, exact source digest, immutable draft history and receipts. Required missing event assessments cannot disappear through an inner join. Each event and subject requires explicit sourced inclusion/exclusion. `GET ?id=<run-id>` inspects immutable input/result manifests.

`POST {action:'calculate',discipline,effectiveDate,rulesId,version,sourceDigest,requestId,evidence}` freezes one synchronous administrative draft and its contributions, audit and receipt atomically. `evidence` is `OverallEvidence` in `src/domain/overall-ranking-input.ts`. The browser supplies ordinary source, coverage, eligibility, continuity and adjustment controls; JSON import is optional. New season subjects/events appear as unresolved when saved evidence is rebased. Starting a new evidence review resets editable inputs while preserving immutable history.

The engine supports the actual2026-27 overall dated schedule; modified schedules remain unsupported even if a source record is reviewed. Calendar checkpoints are inclusive; season end is exclusive. The explicitly labelled application interpretation includes events whose recorded completion date is on/before the effective date. Exact rational event values and starting ownership remain exact through carryover, selection and ordering. Display decimals do not alter them. Frozen event points come exclusively from the latest persisted033 assessment input/result bytes and their digest association. A queued/blocked/missing assessment, revised finalization or dirty current sporting digest blocks consumption until a direct reviewed assessment exists. Original list/award manifests remain unchanged.

Completed033 event-roster review does not approve032 starting rights. Every included subject needs a current **reviewed and complete**032 starting record covering the date, identified official regulars, allocations and individual ownership/eligibility. The separate continuity review either records sourced absence of a floor or exact prior roster/total/shares proving three-of-four/four-of-five retention. Retained amounts must match their sourced prior shares. The floor is `max(individual sum, prior total)`; a stronger incoming right adds the exact difference naturally. Core reuse, old names and public participation grant no rights.

Ordinary adjustments record exact owned award exclusions and explicit retain/exclude decisions when the official ranking roster changed. They cannot assign arbitrary current awards or transfer them through core identity. Optional historical transfer checks verify a current032 entitlement against documentary previous-season played subtotals/final totals under one of five ordinary formula branches. These require independent prior-season applicability source, chronology and rationale; this year's publication does not prove retroactive applicability. They validate the existing entitlement rather than adding a manual list total. Exact October31 transfers and unknown penalties/exemptions remain unresolved; no inferred deadline instant or generic waiver is supplied. Historical values are documentary starting evidence, while every current award remains actual033 evidence.

Equal exact totals use fewer actual counting awards, then successive removal of smallest counted awards, retaining carryover in each reduced total under the recorded application interpretation. Exhausted equal vectors retain null sporting ranks and block readiness. Names/IDs never invent an official final criterion. Biography warnings are separate from required blockers.

`POST {action:'replay',runId,discipline,effectiveDate,requestId}` recomputes only frozen inputs with the matching actual engine/source fingerprint and Node version, requires exact result-digest equality, and records an audit/receipt. No current mutable totals are read. A matching historical build is needed after implementation changes. New calculations create direct replacement revisions; no publication or transitive cascade exists here.

Actor/request and then per-list session advisory locks are acquired on the dedicated connection **before** opening a serializable snapshot. This prevents an append-only033/finalization committed during the list-lock wait from hiding in a pre-wait snapshot and serializes cross-date reuse of one request ID. Current authority and context precede receipt replay. Finally releases both locks in reverse order; an unlock failure destroys the client instead of returning a lock-bearing connection to the pool. There are no broad source-table locks. Concurrent-source serialization failures return409; uncertain failures return503 and require exact-command retry.

Errors:401 sign-in;403 current staff/Origin/actor mismatch;404 missing record;400 malformed evidence;409 stale/conflicting context or delivery;422 unsupported/mismatched historical replay build;503 uncertain acknowledgement. Incomplete factual evidence produces an immutable **blocked** draft with reasons, never a ready list with fabricated values. No public publication, series or mixed-doubles list is implemented by this endpoint.
